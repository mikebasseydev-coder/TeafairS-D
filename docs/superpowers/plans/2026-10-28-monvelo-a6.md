# Monvelo (Addendum A6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Monvelo's backend in eight shippable steps. This plan details **Step 1: roles, areas, recruitment and brand terms**. Steps 2–8 each get their own detailed plan when Step 1 is merged, because each depends on facts the step before establishes (Paystack payer binding, F1, gates Step 3).

**Architecture:**
- Monvelo is a `monvelo_`-prefixed domain inside the existing Supabase backend. It links to the rest of Teafair by id only.
- Spec A §9 applies everywhere:
  - `authenticated` has SELECT only;
  - writes go through SECURITY DEFINER RPCs with `SET search_path = public, pg_temp`;
  - the tenant comes from the JWT, never from the client;
  - every policy is `FOR SELECT`;
  - every mutation takes `p_idempotency_key uuid` first.
- Anything that calls an outside service (Paystack account resolution, WhatsApp) is an Edge Function. It proves itself to the RPC with the Vault `gateway_secret` (ruling R16, `assert_gateway_proof`).

**Tech Stack:**
- Postgres 17 migrations (hand-written), pgTAP;
- Deno Edge Functions (`userGateway`, `observe`, the A5 message router, `paystackGet`), Zod 3.

No Prisma. SecureStore and MMKV belong to the Spec B client and are not in this plan.

**Spec:** `docs/superpowers/specs/2026-10-28-addendum-a6-monvelo-design.md` (approved 2026-10-28).

## Global Constraints

- **Persona codes:** `ZSA`, `ASA`, `ZSM`, `TM`, `ASM`, `RETAIL_SHOP_OWNER`; platform roles `MONVELO_OPERATOR`, `MONVELO_FINANCE`. Never "FSO".
- **New Monvelo tables:** prefixed `monvelo_`. No non-Monvelo function writes them.
- **Money and status types:** money `numeric(15,2)`; rates in basis points (`integer`, 0–10000); statuses `text` + `CHECK`.
- **Tenant-scoped tables:** `tenant_id uuid not null references tenants(id) on delete restrict`, `unique (tenant_id, id)`, composite FKs, every FK and policy column indexed.
- **Function grants:** new functions get no EXECUTE for PUBLIC/anon/authenticated unless granted explicitly.
- **Error codes:** P0001 business 422, 42501 forbidden 403, 23505 409, TF002 idempotency mismatch.
- **No personal data in audit rows or logs:** no full phone number, no account number beyond the last four digits, no code.
- **Defaults from the spec:** interest-free 30 days; late charge 1000 bps; offer radius 1 km. The 3-cash-orders, 25% limit growth, PAR30 10% and 80% flag rules are Step 2+ concerns.
- **Brand matching:** case-insensitive on trimmed text (`lower(btrim(brand))`), as brand tiers do.
- **Sequencing:** migrations start at `20261028120000`; pgTAP files continue at `036_`.

## Review Focus

1. **Brand spelling.** "Purerigin", "PURERIGIN " and "purerigin" are the same brand for terms. A second approved row for any spelling overlapping in time is refused. Owned by Task 6.
2. **Back-to-back promotions.** `valid_to` is exclusive, so terms ending 2026-11-30 and terms starting 2026-11-30 are both allowed; a one-day overlap is refused. Owned by Task 6.
3. **The same POS agent recruited twice** by two street agents (same `pos_network` + `network_agent_id`) gets a 409 with a plain message, not a second agent. Owned by Task 3.
4. **Cross-tenant enrolment.** A ZSA of tenant A enrolling a shop into an area of tenant B is 42501. Enrolling the same shop twice for one tenant replays, not duplicates. Owned by Task 5.
5. **Platform roles without a tenant.** A MONVELO_OPERATOR with no tenant membership can approve agents. A tenant ZSM without the platform role cannot (42501). Owned by Tasks 3 and 6.
